# BUGLOG 2026-11-19

## STUDIES-FEED-ORDER-20261119: stores lane re-ran studies_card after the feed was published and never republished the feed in the same lane

- Severity: high (one lane's Step 0 deterministically re-staled five
  downstream pages on 2026-11-17 and 2026-11-18; both nights the
  pages landed only through a manual finisher).
- File: cron job terminal-daily-stores-refresh (saved definition;
  read-only copy at
  workspace/cron.d/weekly/terminal-daily-stores-refresh__weekly@Mon,Tue,Wed,Thu,Fri-18:46:00_user_current.md).
- What broke: Step 0 of the stores lane re-runs
  `python3 studies_card.py` from ~/workspace/morgue after the
  forecast lane advances the price panel. That rewrite stamps
  output/studies_card.json with a new generated_at (2026-11-18:
  23:49:00Z) while output/morgue-feed.json still carried the
  morgue post-close publication time (22:32:06Z). State Analogue
  in the same lane refused (exit 1, feed does not postdate card),
  and the tools lane's four studies refreshers (refresh_fearday,
  refresh_gapfill, refresh_openingrange, refresh_pullback) refused
  on the same ordering the same night. The lane definition had no
  publish step of its own, so the defect fired every night the
  Step 0 re-run moved the card, by construction.
- Fix: minimum sufficient change at the source. The stores lane
  definition now runs `python3 publish_feed.py` in Step 0,
  immediately after studies_card.py and before any refresher, and
  adds a destination verification: the feed's generated_at_utc
  must not precede the card's generated_at and the feed's studies
  sections must agree with the card. No code, strategy, sizing or
  threshold change. Route considered and rejected: making
  studies_card.py itself publish the feed, because the morgue
  daily cycle calls studies_card mid-cycle, before finra_wait and
  ext_card settle, and an early publish there would ship a feed
  built on unsettled stores; the stores lane is the only
  standalone post-publish rewrite.
- Regression blocker:
  test_studies_feed_order_lane_20261119.py in this directory
  (lane definition ordering assertion plus the live feed/card
  invariant). Fail direction: the pre-cure definition contains no
  publish_feed step, so the ordering assertion fails on it
  (verified against the pre-cure body shape in the cure run);
  2 tests pass on the cured definition, and the pre-existing
  blocker test_morgue_feed_studies_freshness_20261117.py also
  passes (4 passed total, 2026-11-19 audit run).
- Destination proof: cron.view read-back after the update shows
  the new Step 0 text in the saved definition with the schedule
  unchanged (Mon to Fri 18:46 ET). Live pair at cure time: card
  generated 2026-11-18T23:49:00Z, feed generated
  2026-11-19T13:52:33Z, studies sections agree. First scheduled
