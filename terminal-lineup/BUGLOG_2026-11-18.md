## CLOSE-TMP-RACE-20261118: lane close steps died on shared fixed temp names when the hourly and intraday lanes closed concurrently

- Severity: high (terminal publish lane failed three hourly runs in
  one day; pages themselves stayed fresh, the close/publish step is
  what failed).
- Files: site/terminal_common.py (write_data_json and the atexit
  manifest sync), site/record_surface.py (enrich_file),
  site/explanation.py (enrich_file), site/publish_desk.py (desk
  copies and data.json/attractions.json/index.html writes),
  site/refresh_book_strip.py (_atomic_write).
- What broke: hourly lane FAILED 2026-11-18T15:21:37Z, 17:21:52Z
  and 18:21:54Z (pages=104); intraday FAILED at 17:21:52Z and
  18:21:54Z (pages=8), recovering on its own next cycles. Every
  failure was in the close steps with one signature:
  FileNotFoundError renaming a FIXED temp name onto its target
  (data.json.tmp -> data.json across 16 pages at 18:21Z;
  asset-manifest.json.tmp -> asset-manifest.json in the
  terminal_common manifest sync), plus one desk JSON parse error
  inside enrich_all at 18:21Z. Root cause: the hourly lane (:21)
  and the intraday lane (every 5 min) run the identical close()
  concurrently (both stamp the freshness log in the same second),
  and every close writer named its temp as a fixed function of
  the target, so the first writer's os.replace moved the shared
  temp away and the second writer's rename found nothing. This
  is the HUB-ATOMIC-WRITE-RACE-20261110 class, cured in 2026-11-10
  for refresh_hub only; the sibling writers kept the defect. The
  desk parse error was the same concurrency from the read side:
  publish_desk (inside the other lane's refresh_hub) wrote
  desk/data.json with a truncating write_text while this lane's
  enrich_all was parsing it; the desk source data was never
  corrupt.
- Fix: one shared unique-temp atomic writer,
  terminal_common.atomic_write_text (mkstemp in the target's own
  directory, os.replace, temp cleaned on failure), now used by
  write_data_json, the manifest sync, record_surface.enrich_file
  and explanation.enrich_file. publish_desk gained the same
  unique-temp writes (_atomic_write_text) and copies
  (_copy_atomic) for terminal_feed.json, index.html,
  attractions.json and data.json, so no close-step reader can
  see a torn desk file. refresh_book_strip._atomic_write takes
  the per-process temp refresh_hub already uses (name still ends
  ".atomic-tmp", so the sync exclusion is unchanged). No strategy,
  sizing, threshold or engine change; published bytes unchanged.
- Regression blocker: site/test_close_tmp_race_20261118.py
  (6 tests: unique-temp roundtrip, write_data_json temp capture,
  source assertions against the fixed names, two-process
  concurrent atomic writes, two-process concurrent enrich of the
  desk page, publish_desk atomicity). Fail direction proven: the
  pre-cure fixed-temp pattern reproduced in isolation yields the
  exact live FileNotFoundError (data.json.tmp -> data.json), and
  git HEAD's terminal_common has no atomic_write_text, so the
  blocker fails on the old tree; all 6 pass on the cured tree
  (2026-11-18 ~18:52Z run).
- Destination proof: LANDED 2026-11-18T19:21:45Z, the first
  hourly run after the cure and the same collision second that
  failed twice before: lane_freshness.log reads
  "2026-11-18T19:21:45Z lane=hourly result=ok pages=104
  freshest=2026-11-18T19:21:28Z" and, at the same timestamp,
  "2026-11-18T19:21:45Z lane=intraday result=ok pages=8
  freshest=2026-11-18T19:21:19Z". Intraday cycled ok on the
  cured code continuously from 18:41Z through the proof run.
  Verdict GREEN.
