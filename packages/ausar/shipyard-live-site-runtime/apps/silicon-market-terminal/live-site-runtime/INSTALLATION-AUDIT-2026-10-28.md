### Data-pipeline comparison and remaining gaps

The scoped Ausar desk audit showed a producer/worker split: market data is warmed separately from financial consumers; stale or absent latest quotes block entry use; completed history waits for the source's publication delay; and exchange-session pending state is distinct from data failure. Those controls prevent an old cache from looking like a fresh observation.

Shipyard currently uses on-request provider reads and per-isolate caches. Its Chartlector input is an upstream static JSON artifact, generated `2026-10-22 18:33 ET`; production still reports `as_of=2026-10-22` on `2026-10-28`. The Research Engine Suite marks context older than three days stale, but the dedicated Market Context page lacked that badge until the browser-found fix in version 435. Alpaca reports IEX daily bars, not consolidated SIP coverage. No upstream producer refresh, Worker Cron, hosted alert scheduler, durable cross-location cache/rate coordinator, or Python-engine runtime is configured here. The four Python systems remain source-linked; alerts remain browser-local and are checked after refresh.

Research findings: [Alpaca's historical-data guide](https://docs.alpaca.markets/us/docs/historical-stock-data-1) describes IEX as a single-exchange feed and SIP as consolidated U.S. exchange coverage. [Cloudflare's rate-limit documentation](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) says per-location limits are approximate; a strict shared limit needs durable coordination. [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/) provide the scheduled-handler mechanism, but cannot refresh this upstream static artifact until its producer is connected. [Cloudflare Cache documentation](https://developers.cloudflare.com/workers/runtime-apis/cache/) describes data-center-local cache behavior. [Yahoo's Terms](https://legal.yahoo.com/us/en/yahoo/terms/otos/index.html) restrict automated collection and commercial reuse; Yahoo remains a link-out.

Open items are the stale upstream Chartlector producer, the missing source-backed 92-name roster (86 families are evidenced), the five bounded-review families, licensed point-in-time market data, authenticated MCP verification, persistent hosted alerts, global rate/cache coordination, and execution of Python engines behind a read-only adapter. Added `sec_rate_limit.py` and routed those Morgue SEC calls through its 0.12-second file-lock scheduler. The lock coordinates cooperating Silicon processes on this host; it cannot coordinate other hosts or unrelated programs sharing the same public IP. The SEC's current developer guidance sets a total maximum of 10 requests per second irrespective of how many machines submit requests, so the local lock is a conservative improvement, not a global guarantee. See [SEC Developer Resources](https://www.sec.gov/about/developer-resources) and [SEC rate-control notice](https://www.sec.gov/filergroup/announcements-old/new-rate-control-limits).
