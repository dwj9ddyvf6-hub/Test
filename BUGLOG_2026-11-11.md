- What broke: line 17 set GATE_TMP="$PWD/.gate_tmp", a FIXED
  in-repo path. The script rm -rf'd it at start, and the
  EXIT/INT/TERM trap rm -rf'd it again on exit. unittest.log
  lived inside it (GATE_LOG="$GATE_TMP/unittest.log"), so every
  run, pass or fail, ended by deleting its full log; only the
  5-line tail printed to stdout survived. This is exactly how
  the LAND-SHEN-20261110 first-run failure (Ran 1,859 tests,

  from the tail, the evidence was not. The fixed path is also

  unittest, tail printed, exit "$rc" (the GATE-MASK-20261026
  cure) is preserved byte-for-byte in behaviour.

  scratch: GATE_TMP is now `mktemp -d "$PWD/.gate_tmp/run.XXXXXX"`
  under the already-ignored .gate_tmp/ parent (no .gitignore
  change needed); the trap still removes only that per-run dir.
  (2) Receipts on EVERY run, pass or fail, written BEFORE the
  tail/exit and never touched by the trap: the full unittest
  log is copied to state/gate_receipts/unittest-<run-id>.log
  and a one-line JSON proof row is appended to
  state/gate_receipts/receipts.jsonl carrying run_id
  (UTC stamp + pid), timestamp_utc, tree_hash (git rev-parse
  HEAD, "unknown" outside a repo), wall_seconds, ran_line
  (unittest's own "Ran N tests in Xs" line), exit_code and the
  receipt log path. Receipt dir choice: state/ is the repo's
  runtime dir, listed in .gitignore (line 3, `state/`) with
  zero tracked files under it, so receipts are durable on disk
  and never committed. Receipt write failures warn on stderr
  and never mask unittest's exit code. Append-only ledger plus
  per-run logs; no pruning in this cure. Interface unchanged:
  same discovery, same exit codes, same tail -5 for humans.
