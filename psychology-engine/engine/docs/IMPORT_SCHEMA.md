# Import and evaluation schema

Observation input is a JSON array or CSV with these required columns:

`source,item_id,revision,event_time,publication_time,entity,horizon,dimension,units,source_family,access_status,max_age_hours,config_version`

`value` is numeric or null/empty (unknown). `text` and `url` are optional. `first_seen` is required only for `--trusted-historical`; otherwise the program writes actual ingestion time. All timestamps must carry UTC or an explicit timezone offset. Accepted access values for aggregation are public, licensed, user_import and fixture; others are excluded. Dimensions are sentiment, attention, uncertainty, disagreement, positioning, stress and narrative_change; auxiliary price_return with decimal_return units supports divergence detectors. Units must distinguish incomparable scales. Assign different configuration versions when access, units, scoring or freshness policy changes.

Each revision belongs to `(source,item_id,dimension,entity,horizon,units)`. Revisions are immutable; a changed value or provenance must use a new revision identifier. The snapshot picks the latest available revision, with first-seen and publication timestamps defining ordering. Do not submit simultaneous conflicting versions without distinct temporal provenance. Supply original source families for syndicated copies. Exact normalized text is deduplicated across sources; numeric observations are deduplicated within source family, event, dimension, value and units.

The evaluator consumes a separate JSON array with `entity`, `horizon`, `as_of`, `feature_available_at`, `label_end`, `label_available_at`, `price_momentum`, `sentiment`, `target`. Use one entity and one horizon per run, unique chronological decisions, decimal returns, features demonstrably available at the decision and targets measured after it. Label availability is explicit and cannot precede label_end; training requires availability strictly before the decision. Decimal returns are bounded to absolute value 100 to reject corrupted/overflowing inputs; sentiment must be in [-1,1]. This evaluator is deliberately limited and is not a full market dataset builder. Missing sentiment rows are omitted from all compared model samples; do not infer representativeness from complete cases.

Do not import personal correspondence, identifying account information or licensed raw text into a distributable archive. The supplied archive contains generated fixtures, source code, references, documentation and a clearly labeled two-observation CC0 Wikimedia receipt, and excludes runtime databases.

Historical imports require provenance as a JSON object (or a JSON-encoded CSV cell) with provider_received_at, locally_received_at and extracted_at. Required semantic fields include source_population and entity_mapping_version for interpretable attribution; absent fields remain unknown and temporal detectors abstain when population is unknown. For ordinary imports, actual ingestion time sets local receipt and extraction. An existing revision cannot change semantic provenance. Receipt clocks on a repeated fetch never rewrite its original availability. See README for price_return market context and permitted positioning measurement kinds.

## Existing-response receipt input

`import-receipt` accepts a JSON object with nonempty `receipt_id`, `source`, `source_url`, `captured_at`, `payload_utf8`, `payload_sha256` and `usage_scope`. Optional `redistribution_status` remains unknown if absent. Source must be one of the four implemented adapters and HTTPS origin must match its reviewed configured origin. The full UTF-8 response must match its SHA-256, stay within 8 MB and have a capture time no later than import. Adapter schema validation also applies. Every completed event and publication timestamp must be no later than upstream capture; later local receipt cannot legitimize an impossible capture. This is supplied evidence and usage attestation, not independent proof of source authenticity or rights.

Upstream capture is retained in provenance. Current local receipt/extraction and first-seen govern engine availability. Acquisition logs retain envelope hashes, and repeated identical receipts are idempotent. Receipt imports have a distinct run category and do not mark outbound collection healthy. No URL is fetched by this command. Only redistribute source payloads when explicitly permitted; the included Wikimedia example is CC0.
