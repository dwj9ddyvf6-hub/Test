# Psychology Engine — practical blocker resolutions

**Research date:** 2026-10-30 UTC. **Baseline inspected:** isolated `implementation_v031/psychology-engine-research`, source registry of 50 candidates, four implemented remote adapters, four descriptive detectors. This is an actionable research/design addendum, not a claim that the proposals below have been implemented or deployed. It contains no downloaded market database, credentials, or third-party article corpus.

## Decision

**A useful, lawful, reproducible research engine is achievable without buying every feed. “Every limitation eliminated,” continuously live coverage, and validated trading alpha are not established.** Solve software failures; obtain permission for access/retention where necessary; substitute a clearly different construct when exact data are unavailable; abstain where the underlying information genuinely does not exist.

The best initial operating profile is **open-source research code + synthetic public fixtures + approved public-domain/CC0 sources + private provenance-aware imports**. Keep licensed inputs in a separate private data plane. Keep the existing multidimensional output: attention, policy language, risk pricing, positioning, and news tone are not interchangeable measures of one universal emotional state.

**Completed in this pass:** inspected the baseline and registry, verified primary-source policies and operating documentation, identified a canonical Cboe endpoint change, specified testable fixes and remaining gates, and checked the local SQLite runtime (`3.53.1`). **Not completed:** live collection, source agreements, human labeling, empirical market validation, hosting, schedules, public publishing, or changes to the baseline code. Engineering changes by other workstreams must have their own receipts. The document cites 42 distinct primary-documentation URLs. Documentation retrieval is not an engine ingestion test; the Cboe CSV returned an unsupported-content-type result in the research tool, and the dynamic CFTC public-reporting page exposed no readable lines. Its route is supported by the official CFTC documentation, but its data interface was not validated in this pass.

## 3. Supported architecture options, without restriction circumvention

1. **Approved collector in the present environment — true access fix where allowed.** First establish whether failure is a parser bug or a real network rule. A schema repair must fail closed on unknown/invalid policy, enforce exact approved hosts and HTTPS, and revalidate publisher-directed endpoint changes. Do not edit the managed network-policy file. If genuine denial remains, the specific needed action is an administrator-approved source-host allowance, not a proxy.
2. **Separately authorized operator collector — conditional deployment alternative.** If the user chooses a desktop/remote service and that environment independently permits these sources, prepare the same bounded collector with local durable storage. Do not move there automatically because this environment denied access. Obtain authorization for target machine, outbound domains, contact identity, retention and operation before activation.
3. **Offline import bridge — degraded timeliness, full reproducibility.** Accept data the user already lawfully possesses through an approved transfer. Each batch includes source/purpose rights, collection timestamps, schema/config version, checksum and coverage. Import normally with actual local receipt/extraction. Historical first-seen can be supplied only with independently auditable evidence. A checksum proves byte identity, not authenticity, licensing, or historical availability. Do not use a browser/proxy to ferry denied live source requests into the engine.
4. **Licensed official provider interface — conditional exact coverage.** If an existing connector supplies the required data within its authorized service scope, validate actual entitlements, identifiers, feed, history and export terms. A connector's presence or a 200 response does not prove all-market coverage. Do not create accounts, purchase subscriptions, request keys, accept contracts, or change subscriptions in this research pass.
5. **Public-safe presentation plane — true leakage reduction.** Export code, research notes, fixture-derived examples, and capability/health descriptions separately from raw/private evidence. A data-derived signal remains withheld unless its permitted derived-use/export scope is established. The public page can show “unavailable/awaiting permission” rather than silently filling a proprietary field with another series.
6. **Capability negotiation instead of all-or-nothing “psychology.”** Each output declares which dimensions/populations are observed, stale, modeled, or unsupported. A missing VIX adapter should disable VIX-specific stress persistence, not crash the attention pipeline or produce a fake zero. Substitutes have new IDs, units, normalization and model versions; revalidate their downstream detector.

No architecture above has been activated. This research does not broaden authority to deploy, subscribe, publish, change network policy, or send alerts.

|---|---|---|---|

These ceilings are not target throughput. [Current rate policy](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)

SEC API authentication/bulk facts: [API documentation](https://www.sec.gov/search-filings/edgar-application-programming-interfaces). Rate limits are per user across machines: [developer resources](https://www.sec.gov/about/developer-resources).

### Proposed service design

- One collector/writer process, short transactions, atomic successful-batch commit; readers do not mutate ingestion state. Persist last successful batch/checkpoint on verified persistent local disk. Use a process lock or supervisor singleton rather than hoping collectors do not overlap.
- Source-specific states: `not_authorized`, `not_due`, `fetch_ok_no_change`, `fresh`, `late_release`, `stale`, `rate_limited`, `access_denied`, `parse_failed`, `schema_changed`, `coverage_unknown`, `rights_expired`. Preserve separate request time, observation time, publication time, receipt time and computation time.
- For transient 429/503/timeouts, obey server delay and bounded exponential backoff with jitter and a total request/time budget. A long `Retry-After` ends a finite run with a resumable due time; it is not ignored. 401/403/policy denial stops dependent work. Validate content type, bytes limit, schema, units, monotone clock assumptions and coverage before commit.
- Alert on changed actionable state, not every unchanged failure; external alert destination and recurrence require authorization. Keep local structured receipts usable without external telemetry.
- Back up through SQLite's supported online backup API or a consistent closed database, not by copying only the live `.sqlite` file while WAL may contain commits. Restore into a new path, run integrity checks, compare row/revision/checkpoint counts and replay a known snapshot. [SQLite backup API](https://www.sqlite.org/backup.html)
- WAL permits concurrent readers but still one writer and requires the same host; do not place WAL on a multi-host network filesystem. Check the target's linked SQLite version. Official documentation reports a rare WAL-reset race fixed in 3.51.3 and certain backports; this container reports **3.53.1**, but that proves nothing about a future deployment target. [SQLite WAL documentation](https://www.sqlite.org/wal.html)
- Set a data-loss and recovery-time objective with the operator before choosing backup frequency. Use private backups only where their storage/retention is allowed. Backups are not permission to retain data indefinitely.

## 6. Historical vintages, labels and empirical validation

### A. Availability tiers

1. **Audited contemporaneous receipt:** highest-quality forward evidence; retain payload/version hash, receipt, extraction, source timestamp and model/config IDs.
2. **Publisher archived vintage with verified release:** suitable for historical work at its actual clock resolution; separately record when this project acquired it.
3. **Date-only verified vintage:** valid only with an explicit conservative availability convention; use next eligible decision session if intraday release is unverified, with sensitivity analysis. This is an assumption, not a reconstructed receipt.
4. **Current revised historical series:** descriptive/exploratory only unless the study's information timing explicitly permits it. Never backdate the engine's first-seen clock or mark it a proven real-time dataset.
5. **Synthetic fixture:** software correctness only; excluded from empirical score/coverage denominators.

For every forecast, form the information set at cutoff from data actually available then. Separate target observation end from target publication/label availability. Future revisions may be scored as a separate target, never substituted silently for the originally declared first-release target.

### B. Specific historical routes and limits

- **ALFRED:** supports `realtime_start/realtime_end` and [series vintage dates](https://fred.stlouisfed.org/docs/api/fred/series_vintagedates.html). The vintage-date endpoint omits unchanged release dates; it is not a complete release calendar. [API key policy](https://fred.stlouisfed.org/docs/api/api_key.html) requires a registered key; no key was requested here. Verify actual archive depth and series copyright before use.
- **SPF:** official [Dates of Previous Surveys file](https://www.philadelphiafed.org/-/media/FRBP/Assets/Surveys-And-Data/survey-of-professional-forecasters/spf-release-dates.txt?hash=CE16E2057464DBD7A139FFE6188B48EC&sc_lang=en) and source-specific errata support more defensible historical timing. The [real-time macro data set](https://www.philadelphiafed.org/surveys-and-data/real-time-data-research/real-time-data-set-for-macroeconomists) supplies macro vintages, not universal sentiment vintages.
- **COT:** full historic values do not imply complete historic release dates. Preserve the official calendar available now and require evidence for older exception dates; if missing, bound availability conservatively or exclude those test periods. Its October 27 announcement plans a change by end-2026, not immediate activation. [Current calendar](https://www.cftc.gov/MarketReports/CommitmentsofTraders/ReleaseSchedule/index.htm)
- **SEC:** acceptance timestamp is not first public availability. SEC describes typical dissemination lag of 1–3 minutes but no guarantee and no timestamp for first public availability. Use forward first-seen or conservative latency analysis for historical intraday tests. [SEC timestamp FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions)
- **NY Fed SCE:** core/credit-access microdata have nine-month lag; several other modules eighteen months. Do not use late microdata to simulate what a monthly live aggregate collector knew. [SCE FAQ](https://www.newyorkfed.org/microeconomics/sce/sce-faq)
- **OFR FSI:** published values are two business days behind, and the current page documents specific corrected observations. This makes it a useful revision-test case, not a contemporaneous substitute for VIX. [OFR FSI](https://www.financialresearch.gov/financial-stress-index/)

### C. Two independent labeling problems

**Text measurement validation:** Define entity, speaker, target, valence, uncertainty, horizon, quote/negation handling and “cannot determine.” Sample by source and time, deduplicate the event across splits, obtain two independent human labels and adjudication, preserve disagreement rather than treating every ambiguous text as wrong. Use an exploratory pilot to repair the rubric; freeze it before final evaluation. Report per-class precision/recall, confusion matrix, abstention-versus-coverage, human agreement and source/language subgroup failures. Human requests or paid annotation are not initiated by this document.

**Forecast validation:** Define an observable target, exact instrument/venue, decision clock, horizon, adjustment policy, first-release versus revised outcome, and executable cost model. A “bullish” text label is not a future-return label. Construct target data only from authorized sources and make `label_available_at` explicit. Daily Treasury yields cannot substitute for equity total returns; an attention forecast cannot be advertised as a profitable equity strategy.

### D. Proposed promotion gates

1. **Engineering gate:** deterministic fixtures and adverse cases pass; exact implemented capability list published; no market claim.
2. **Data gate:** actual rights/canonical endpoint/coverage/clock audit, durable repeat acquisition, restart and restore proof. No passage of time or count of successful HTTP calls alone proves data quality.
3. **Measurement gate:** frozen human-labeled holdout meets prospectively chosen accuracy/coverage bounds; unvalidated dimensions abstain.
4. **Retrospective forecast gate:** chronologically split development/validation/final test; fit preprocessing, feature choice and calibration only within training; purge actual overlapping labels and use time-based gaps. `TimeSeriesSplit` is not sufficient by itself for irregular release events or overlapping labels; official documentation expects equally spaced samples for comparable-duration folds. [Time-series split documentation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
5. **Incremental-value gate:** compare the augmented model with persistence, historical mean and the price/volatility baseline at identical cutoffs and common samples. Report missingness and source ablation; common-case selection is a limitation. Freeze the hypothesis/search budget and retain failed candidates. Estimate uncertainty with time/event dependence respected; set sample duration/effective opportunities from the detectable improvement, not an arbitrary “100 trades.”
6. **Probability gate:** held-out proper scores plus reliability/coverage diagnostics; lower Brier score alone is not proof of better calibration. [Calibration documentation](https://scikit-learn.org/stable/modules/calibration.html)
7. **Forward-shadow gate:** freeze the full policy and collect prospective forecasts before outcomes. Compare only on predeclared review dates/rules; adding data or tuning after every loss does not create an untouched test. Duration depends on target cadence and independent opportunities.
8. **Economic/deployment gate:** demonstrate improvement after realistic latency, fees, spreads, impact and relevant risk; validate portfolio contribution separately from standalone return. No real-money integration is authorized here; Tensor retains entry timing authority.

**Status:** none of the new empirical gates is passed by this research document. Existing generated tests are engineering evidence only. The first highest-value experiment is a small rights-cleared, point-in-time dataset with one frozen target and one cheap baseline—not simultaneous optimization over fifty sources and sixteen hypotheses.
