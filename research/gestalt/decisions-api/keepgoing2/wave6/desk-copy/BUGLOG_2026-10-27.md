## BROKER-422-BODY-20261027
- Severity: high (diagnosability). Area: desk3/netfetch.py,
  desk3/dispatcher.py.
- Broke: on an HTTP error the broker response body was read and
  discarded in netfetch.fetch_bytes; FetchError carried only the
  status, so every broker 422 reached the dispatcher journal as a
  bare "FetchError:HTTP 422 for .../v2/orders" and the failing
  field was unknowable from desk records (STAGE-C-PROGRESS
  diagnostic note 2026-10-26). The journal also recorded no payload.

  fetch_bytes attaches the decoded body on status >= 400, and the
  message carries it so every existing str(error) journal gains it.
  The dispatcher's broker_unavailable journal row now also carries
  error_body plus the exact submitted payload (symbol, side, qty,
  order_type, limit_price, time_in_force).

  (4 tests: body in message+attribute, old no-body shape preserved,
  live local-HTTP 422 body reaches the caller, dispatcher journal

  old FetchError has no .body and old journal rows have no
  error_body key.
- Proof: scoped run on the cured tree (see EXECUTE remainder R6
  report); the cure's first live use captured the three 422 bodies
  below within the hour.
