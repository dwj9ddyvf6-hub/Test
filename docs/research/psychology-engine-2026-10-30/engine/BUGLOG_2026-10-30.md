# Bug Log, Psychology Engine, 2026-10-30

## BUG 1: Synthetic test compile overwrote the real published state

- Severity: high (final-artifact integrity).
- File: pipeline.py, compile_state; tests/test_engine.py.
- What broke: compile_state always published its outputs (state JSON,
  STATE.md, and the consumer SENTIMENT-STATE files). The acceptance tests
  call compile_state with synthetic gauge rows, so running the test suite
  after the real compile replaced the day-one state (Fearful, 24.6) with
  a synthetic state (Neutral mix, 50.7) in every published surface.
- Fix: compile_state gained publish=True as a parameter; every test calls
  it with publish=False. The real state was recompiled from the store and
  the page and consumer files regenerated.
- Regression blocker: test_synthetic_compile_never_publishes in
  tests/test_engine.py hashes the published state before and after a
  synthetic compile and fails if it changes. Verified: suite passes and
  the published state after the suite is the real compile.
- Proof: state after cure reads Fearful, composite 24.6, generated by the
  real compile; 8 tests pass.

## BUG 2: Failed re-pull overwrote the landed GDELT series with an absent file

- Severity: high (stored-history destruction on a transient failure).
- Files: psychology_engine.py (write_series, write_absent), pipeline.py
  (every collector exception handler, 14 call sites including bf_gdelt).
- What broke: bf_gdelt landed 71 tone rows (2026-08-02 to 2026-10-27). A
  later re-pull failed (GDELT curl exit 22) and its exception handler
  called write_absent, which unconditionally rewrote
  history/series/gdelt_gkg_tone_daily.csv as an empty absent file. The
  published state and G7 gauge still claimed 71 observations, so G7
  coverage did not match the stored series and G7 could not be
  recomputed from it. Every collector using the same
  write_absent-on-exception pattern (15 occurrences in pipeline.py
  including the import) could silently destroy stored history the same
  way, including on the daily lane (live_collect routes through the
  same bf_* collectors).
- Fix: cured at the source in psychology_engine.py. write_series now
  refuses to overwrite stored rows with an empty row set, write_absent
  only records an absence where no data is stored, and a new
  preserve_series is the failure-path entry point. All 14 pipeline call
  sites (every exception handler plus bf_absent_series) now call
  preserve_series; the bf_gdelt failure log line also records the
  preserved count and span. The GDELT series was restored from the
  stored raw snapshot (live/raw/backfill_attention/2026-10-30/
  gdelt_tone.json, sha 7f2b862241ffe49794ba24ffed88b08d320e90555567d7d),
  then bf_gdelt was re-run live: the first re-run failed again with
  curl exit 22 and the 71 rows survived intact (the exact failure that
  destroyed them before the cure), and a second re-run succeeded,
  returning byte-identical data (same file sha). Gauges were
  recomputed and the state recompiled and the page re-rendered.
- Regression blockers: test_failed_pull_never_destroys_stored_series,
  test_absent_written_only_where_no_data_stored, and
  test_g7_recomputable_from_stored_gdelt_series in tests/test_engine.py.
  The first two fail on the old code (write_absent erased a 2-row stored
  series in the fail-first reproduction) and pass on the fixed code;
  the third recomputes G7 expanding percentiles from the stored GDELT
  series and compares dates, count, and values against the gauge file.
- Proof: final series file holds 71 rows, downloaded_span
  2026-08-02 to 2026-10-27; recomputed G7 gauge is byte-identical to
  the stored gauge (71 rows); compiled state reads G7 observations 71,
  as of 2026-10-27, value 1.41, regime Fearful, composite 24.6;
  11 tests pass. The forecast ledger was not touched.
