## A. The memory benchmark layer

### A.1 LoCoMo — snap-research/locomo (1,255 stars, last push 2024-08-13, ACL 2024)

**What it actually is (verbatim structure from README.MD).** "a high-quality evaluation benchmark consisting of *very* long-term conversational data. The benchmark consists of ten conversations. Each conversation is annotated for the **question-answering** and **event-summarization** tasks." Conversations are synthetic: generated between two LLM agents with pre-assigned personas (MSC-derived), with images represented only by BLIP captions and search queries (images not released). QA categories in the released data: single-hop, multi-hop, temporal, open-domain, and adversarial (category 5). The QA set in the form every vendor harness uses is 1,540 questions (the count in mem0ai/memory-benchmarks and in the audit below).

**What it measures and does not.** Fact recall and reasoning over one long two-person synthetic conversation history per sample. It does NOT measure: knowledge updates as a first-class category (BEAM's own comparison table marks LoCoMo KU = absent), instruction/preference following over time, memory *writing* fidelity (extraction precision), or abstention in any published vendor run (see A.8).

### A.2 LongMemEval — xiaowu0162/LongMemEval (1,184 stars, ICLR 2025, MIT)

**Verbatim:** "500 high quality questions to test five core long-term memory abilities: Information Extraction, Multi-Session Reasoning, Knowledge Updates, Temporal Reasoning, Abstention." Question types: `single-session-user`, `single-session-assistant`, `single-session-preference`, `temporal-reasoning`, `knowledge-update`, `multi-session`, plus `_abs` abstention instances (30, skipped in retrieval evaluation). Three variants with materially different difficulty: `longmemeval_s` (~115k tokens, ~40 sessions), `longmemeval_m` (~500 sessions), and `longmemeval_oracle` (evidence sessions only). Scoring is an LLM judge (`evaluate_qa.py`, GPT-4o in the reference invocation). **2025-09 cleaning:** histories were re-cleaned "to prevent interference on answer correctness" (cleaned HF release); scores against the original and cleaned releases are not strictly comparable, and vendor posts rarely say which they used.

### A.3 LongMemEval-V2 — xiaowu0162/LongMemEval-V2 (199 stars) — NEW, neither pass knew it existed

**Verbatim:** "evaluates whether memory systems can help agents acquire the experience needed to become knowledgeable colleagues in customized environments… 451 manually curated questions, 5 memory abilities, up to 500 trajectories per haystack, up to 115M tokens." The five abilities are not fact recall: **static state recall, dynamic state tracking, workflow knowledge, environment gotchas, premise awareness**, over web-agent trajectories (web + enterprise domains), with latency scored alongside accuracy and a fixed reader (Qwen3.5-9B in the paper runs; judge default GPT-5.2-medium). This is the first benchmark in the set whose target is *procedural/experiential* memory (how this environment works, what traps recur), i.e. the layer the doctrine's rationale-memory discipline (#11 in pass 2's numbering) and instincts discipline address, which LoCoMo/LongMemEval cannot grade at all.
**Verdict: ADOPT-IDEA** (as the design template for a local experience-memory eval: workflow-knowledge, gotcha, and premise-awareness probes over logged trajectories, with latency reported; do not chase the 115M-token haystack form). **Confidence effect: CONFIRMS discipline 11 (rationale memory)** — an independent, peer-track benchmark now defines rejected-path/gotcha/premise knowledge as a measurable memory ability, which is exactly what rationale entries store.

### A.4 ConvoMem — SalesforceAIResearch/ConvoMem (26 stars, arXiv 2511.10523, Apache-2.0)

**Verbatim:** "75,336 question-answer pairs across six evidence categories": User Facts 16,733; Assistant Facts 12,745; Changing Facts 18,323; Abstention 14,910; Preferences 5,079; Implicit Connections 7,546; 40% single-message evidence, 60% spread over 2-6 messages; test cases mix evidence conversations with fillers at 2 to 300 total conversations. Generation is heavily validated (answerability, necessity, and per-message necessity tests with up to 20 regeneration attempts). It is synthetic and template-shaped compared with LoCoMo's persona dialogues, and its harness is a Scala/Gradle framework, which plausibly explains the tiny adoption footprint (26 stars) despite the largest question count in the set.
**Verdict: REFERENCE.** Its category design (especially a 14,910-item abstention slice and a dedicated changing-facts slice) is the useful takeaway for a local eval set; the benchmark itself is not a vendor-comparable standard.

### A.5 BEAM — mohammadtavakoli78/BEAM (167 stars, ICLR 2026, arXiv 2510.27246) — NEW

**Verbatim:** "100 conversations and 2,000 validated questions" at 128K / 500K / 1M / 10M tokens, ten abilities: Abstention, Contradiction Resolution, Event Ordering, Information Extraction, Instruction Following, Knowledge Update, Multi-Session Reasoning, Preference Following, Summarization, Temporal Reasoning. Its comparison table is the cleanest published statement that LoCoMo lacks knowledge-update and contradiction coverage and LongMemEval lacks contradiction resolution, event ordering, and instruction following. The companion framework **LIGHT** (episodic memory + working memory + a scratchpad that iteratively compresses salient facts/instructions after each turn) improves backbones by "3.5%–12.69%" over the strongest baselines on BEAM.
**Verdict: REFERENCE for the benchmark; ALREADY-HAVE for LIGHT's three parts** (episodic store = file memory, working memory = session context, scratchpad = nightly synthesis/static profile). The one sharpening worth noting: LIGHT's scratchpad is updated *per turn*, not nightly — a cadence difference, not a new mechanism (see looked-and-empty note on cost: no per-turn synthesis cost data is published in the README).

### A.6 PersonaMem — bowen-upenn/PersonaMem (204 stars, COLM 2025, arXiv 2504.14225)

Dynamic user profiling: static + evolving persona attributes, multi-session interactions, 32k/128k/1M context versions, multiple-choice questions across 7 in-situ query types. **Load-bearing result, verbatim sense from README:** the best frontier models (GPT-4.5, GPT-4.1, Gemini-1.5) "still hover around 52% in a multiple-choice setting" at long context, and reasoning models show no advantage. Systems recall facts/preferences well and fail at *applying* a profile to novel suggestions.
**Verdict: REFERENCE.** **Confidence effect: WARNING (mild) to the profile-split adoption (pass-1 Shortlist #4 / pass-2 #7).** The split is still right, but PersonaMem shows a stored profile's hard part is downstream application, not recall accuracy; a local memory eval that only asks recall questions (the MemoryBench shape adopted in pass 1) will overstate profile quality. Add at least one application-style probe type (recommend/choose given the profile) to any local set.

### A.7 HaluMem — MemTensor/HaluMem (178 stars, EMNLP 2026, arXiv 2511.03506, CC-BY-NC-ND) — NEW

**Verbatim motivation:** existing frameworks "treat memory systems as black-box models, assessing performance only through end-to-end QA accuracy" and never examine "the core operational steps." HaluMem scores three operations separately: **Memory Extraction** (recall of reference memory points AND precision/accuracy of extracted points, plus False Memory Resistance), **Memory Update** (correct / hallucination / omission rates), and **QA** (correct / hallucination / omission). Published leaderboard (HaluMem-Medium, from the repo's table): MemOS leads extraction F1 79.70% and QA correct 67.23% with QA hallucination 15.17%; the table also evaluates Mem0 (standard and graph), Memobase, Supermemory, and Zep (full per-system rows are in the repo; only the leader row is quoted here to avoid transcribing an image-adjacent table wholesale).
**Verdict: ADOPT-IDEA.** This is a genuine gap in the adopted set: passes 1-2 adopted QA-shaped memory evals and extraction *prompts*, but no operation-level scoring of whether extraction itself hallucinates or an update silently omits. A small local version (score extraction precision and update hallucination/omission on the nightly synthesis's own changes) is cheap and directly serves the false-green discipline's spirit. **Confidence effect: EXTENDS discipline 7 (memory discipline at numeric level) and discipline 12 (freshness)** — neither is contradicted; both gain a missing measurement axis.

### A.8 The LoCoMo audit — dial481/locomo-audit (22 stars, CC-BY-NC-4.0) — the dive's most consequential find

An independent, primary-source-linked audit of LoCoMo and of published LoCoMo results. Findings, verbatim from its README table:

- "99 of 1,540 questions (6.4%) have wrong golden answers. Theoretical scoring ceiling is 93.57%."
- "62.81% of intentionally wrong vague-but-topical answers accepted by the LLM judge."
- Category sample sizes "range from 96 to 841 (8.8x ratio)… Open-domain (n=96) requires a 15+ point gap to distinguish any two systems… Only Mem0 documents a multi-run methodology; most systems report single-run point estimates."
- "446 adversarial questions (22.5% of dataset)… and no published LoCoMo result evaluates them" (category 5: the abstention slice is silently dropped by published harnesses).
- A full-context baseline with a chain-of-thought answer prompt (GPT-4.1-mini, 92.62%) "exceeding EverMemOS (92.32%)… The answer prompt, not the memory system, explains the score."
- Third-party reproducibility failures quoted (a claimed 92.32% reproduced at 38.38% in a linked issue), and token-cost misrepresentation in a vendor README (claimed 2,298 avg tokens vs 6,669 in its own paper table).

**Verdict: REFERENCE (methodology), with a direct confidence effect (below).** The audit is one small repo, but every claim links to a verifiable primary source (dataset file SHA-verified against upstream, judge prompts SHA-verified), which is the evidence standard this sweep uses.

**CONFIDENCE CHANGE — WARNING to disciplines 4 and 7 (memory profile/graph discipline; memory discipline at numeric level), as evidenced in passes 1-2.** Pass 1's evidence lines for Supermemory and Mem0 leaned on LoCoMo/LongMemEval headline numbers. After the audit, LoCoMo QA percentages must be read as: capped at 93.57% by label errors, inflated by a lenient judge (vague-but-topical wrong answers accepted 62.81% of the time in the audit's stress test), silent on the adversarial/abstention fifth of the dataset, and confounded by answer-prompt choice at the top of the range (a full-context baseline beats the leading memory system when the prompt changes). This does NOT overturn any adoption (the adopted items are mechanisms: profile split, typed edges, ADD-only extraction, fusion formula — none depends on a benchmark rank), but it **retires LoCoMo rank as supporting evidence** for them. Any local memory eval should inherit the audit's lessons instead: verify gold labels on its (small) probe set, include abstention probes and actually score them, use a strict judge prompt, and report the answer prompt as part of the result.

## B. Lineage behind the adopted ideas

### B.1 MemGPT / Letta research artifacts — arXiv 2310.08560 (Packer et al., UC Berkeley)

The paper's evaluation is pre-LoCoMo and explains why Letta has no score in A.9. Two domains, verbatim from the abstract: document analysis (multi-document QA from the "lost in the middle" setup, plus a new **nested key-value retrieval** task where a value is itself a key) and multi-session chat (an augmented Multi-Session Chat dataset with two new tasks). Headline table (deep memory retrieval, LLM-judged accuracy): GPT-3.5 Turbo 38.7% → **66.9%** with MemGPT; GPT-4 32.1% → **92.5%**; GPT-4 Turbo 35.3% → **93.4%**. (Caution worth recording: the GPT-4 figure 92.5% is a numerical coincidence with Mem0's LoCoMo 92.5 — different task, dataset, and decade of models; the two must never be conflated in doctrine text.) Document QA finding: fixed-context accuracy degrades as documents are added; MemGPT's does not, though it "often stopped paging before finding the gold document." Released artifacts named in the paper: augmented MSC dataset, nested-KV dataset, embeddings for 20M Wikipedia articles, benchmark code (research site). The current letta repo's V1 artifacts were already read in pass 2 (archive branch); the lineage point new to this dive is that **the paging idea was validated on retrieval tasks, not on preference/profile memory** — consistent with pass 2's larger borrowable set being about file organisation (MemFS, indexes, editing doctrine), not about recall quality.
**Verdict: REFERENCE (already the standing verdict's basis); no change to ALREADY-HAVE.**

Pass 2 read the awesome-proactive-agents list's README and pilot in full, but neither pass chased the list's *cited systems* for code. - **Cheap-gate convergence, verbatim:** "three independent 2026 papers (PRISM's deliberation gate, the temporal-graph trigger, pre-reasoning perception) converge on a **cheap-gate / expensive-actor** architecture, a convergence the field itself has not yet remarked on." The adopted design (scorer first, separate judge gate second) is the same architecture; **CONFIRMED, strengthened** — it is now a three-paper convergence, not a two-repo pattern.
- **PRISM's gate, as described by the list:** "Intervenes when calibrated P(user acceptance) exceeds a threshold **derived from asymmetric costs of missed help vs false alarms**; −22.78% false alarms, +20.14% F1 on ProactiveBench." Still **no standalone code repo found** (searched again this dive; arXiv 2602.01532 only) — looked-and-empty, as in both prior passes. The gate design remains a paper description to build from, exactly as pass 2 concluded.

**The 3 most substantial codebases among/near the survey's systems not covered by either pass:**

1. **volcengine/MineContext (5,542 stars, pushed 2026-05-07) — the deployed-product counterexample.** A proactive partner built on continuous screenshot capture and comprehension: it "actively delivers… daily/weekly summaries, to-do lists, and activity records" pushed to a homepage, local-first storage, Doubao/OpenAI/local models. ### C.1 Flagged: high-signal, inspected by NEITHER pass

**thedotmack/claude-mem (107,386 stars, Apache-2.0, pushed 2026-10-31) — the largest memory repo neither pass saw.** It appears only under topic:ai-agents (not tagged agent-memory), which is why both passes' memory-cluster searches missed it. **plastic-labs/honcho (7,855 stars, AGPL-3.0, pushed 2026-10-31) — the actual Honcho.** Pass 1 inspected only plastic-labs/codex-honcho (66 stars), the thin Codex harness, and recorded "the memory logic is the key-gated hosted API."
