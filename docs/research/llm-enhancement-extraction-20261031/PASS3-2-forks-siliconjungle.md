### A.1 obra/superpowers forks

**pcvelz/superpowers ("Superpowers Extended for Claude Code") — 1,323 stars, ahead 859 / behind 4, pushed 2026-10-21. INSPECTED (README in full).**
A Claude Code-only fork whose stated reason to exist is that upstream is cross-platform, so Claude Code-native features fall outside upstream scope. Deltas, with the load-bearing one first:

1. **User-Thrown Gate Enforcement (NEW FIND).** The fork names a failure mode neither pass recorded, verbatim: "the user says 'add a gate' or 'verify it works' without specifying **how**, the agent invents a verification method, then finds it expensive at execution time and walks around it — closing the gate with an inline shortcut." The fix is a three-layer architecture: (i) at plan authoring, `writing-plans` silently tags any task whose brief contains gate language ("verify", "prove", "gate", "first on one then all", "make sure", "don't proceed until") with `userGate: true`, using "the stricter definition: strict user gates AND strict agent gates AND gray-in-between all get tagged", and asks the user nothing ("Better to over-tag and let the execution-time hook filter than to over-question the user mid-plan"); (ii) at task close, PostToolUse and Stop hooks fire on tagged tasks and the agent must either post evidence in the form `AC: <criterion> — PROVEN BY <evidence>` or, when it does not know how to verify, invoke a `/specify-gate` command that asks the user 3-4 structured questions locking down the HOW (observable outcome, proof mechanism, scope, failure policy); (iii) the user "is only interrupted at execute time, and only when the alternative is the agent making something up." **Verdict: ADOPT-IDEA**, as an extension of landed discipline #8 (mechanical completion gates) and #10 (execution ledger discipline): the done-gate pattern checks that evidence accompanies a completion claim; this adds tag-at-authoring for user-ordered verifications plus a specify-the-HOW protocol for the case where the verification method itself is unspecified, which is exactly the case a bare evidence check cannot catch (the agent supplies *some* evidence, for a method it invented). One divergence to note and not copy: both hooks "fail-open on errors" with env-var kill switches; the doctrine's gates fail closed.
2. **Pre-commit Task Gate**: a plugin hook "blocks `git commit` when tasks are incomplete". A third independent instance of commit-boundary gating (with pass 2's Agent Guard commit scan and the done-gate), from a different author and motivation. See confidence verdict D.1.
3. **Hook-enforced model routing**: a plan gate blocks task creation when the task's metadata lacks a valid `modelTier` (mechanical / standard / frontier); a dispatch gate blocks agent dispatches outside the union of in-progress tasks' tiers. Its stated rationale, verbatim: "Skills prose is not enforcement; agents skip instructions under load. So every layer here is executed by Claude Code's hook system, not volunteered by the model." The tier names and economics duplicate pass 2's SDD model-selection material. **Verdict: ALREADY-HAVE** (workflow scripts here choose models at dispatch); the creation-time metadata block is a variant worth noting, not a new mechanism.
4. **Structured task metadata**: each plan task carries Goal / Files / Acceptance Criteria / Verify plus a machine-readable `json:metadata` fence embedded in the task description, because (verbatim) "`TaskGet` returns the description but not the `metadata` parameter. This ensures metadata is always available." A small survivability pattern: embed machine-readable metadata inside the human-readable field that lossy channels actually return. **Verdict: REFERENCE.**
5. **Architect pattern**: an executing session messages the separate plan-writing session, which "acts as the architect and answers design questions, while executors work with a focused context." **Verdict: ALREADY-HAVE** (parent/child agent messaging with a coordinator holding the plan).

**REPOZY/superpowers-optimized — 144 stars, ahead 242 / behind 400, pushed 2026-10-10. INSPECTED (README in full).**
A "production-grade" rework: automatic 3-tier workflow routing (micro / lightweight / full, skipping skill loading for simple tasks), safety hooks, and a four-file cross-session memory stack. Two mechanisms are new relative to passes 1-2:

1. **Omission-disclosed budgeted injection (NEW FIND, small).** Its memory hook fills a fixed injection budget (~9,500 characters of a 10,000-character platform cap) in a stated priority order (state, map staleness, critical constraints, open known issues, two latest session-log entries, rest of map, snapshot), and whatever does not fit is named in the injected output itself, in forms the README reproduces verbatim: *"omitted: Directory Structure, Key Files…"*, *"Not shown for size — read when relevant: session-log.md…"*, "so the model knows to open the file instead of assuming it saw everything." **Verdict: ADOPT-IDEA (micro-transfer)** to landed discipline #7 (memory discipline): injected context should declare its own omissions, the injection-layer twin of honest tiered recall. Cheap to land wherever context is assembled under a budget.
2. **In-context self-consistency at verdict points (NEW FIND, small).** `systematic-debugging` Phase 3 and `verification-before-completion` are modified so that "before committing to a root cause or a completion verdict, the agent reaches an answer from 3–5 deliberately different starting points and votes. No majority means a hard stop — gather more evidence before touching code." The fork is unusually honest about the approximation, verbatim: "the paper's paths are separate samples, while these are written in one response and share the agent's blind spots. So the skills treat disagreement as strong evidence and agreement as weak, and the test or command — never the vote — proves the answer." **Verdict: ADOPT-IDEA (small)**, refining pass 1's optillm self-consistency / best-of-N adoption: the transferable unit is not sampling infrastructure but a bounded multi-start vote at the two verdict moments (root cause, completion), with disagreement-as-signal and the vote explicitly denied proof status.
3. Confirmations recorded, not adopted separately: session-log entries marked `[superseded by ...]` are "never injected, because an overturned decision reads as current and is worse than no decision at all" (supports landed disciplines #3 rationale memory and #7); a `state.md` older than the latest commit "is framed as possibly stale rather than 'resume from here'" (supports #4 freshness). A **context-pressure gate** (a hook "blocks plan execution at ≥60% context") is a concrete threshold form of the configured-is-not-active / bounded-loop family. **Verdict: REFERENCE.**
4. **Warning-grade material, not evidence:** the README's research section claims a 76% token saving from Bash output compression and cites a paper (arXiv 2602.11988, "Evaluating AGENTS.md", as cited there) for the claim that repository context files raised task cost 20-23% without improving success. Neither figure was verified in this dive; the citation could not be checked from primary material here and the savings figure is the fork's own. Logged as an unverified caution attached to always-on context files, explicitly not a confidence change (see D.4).
