## 1. Executive summary

**The headline finding: this stack does not need a new platform. It needs a small set of sharper operating rules for the systems it already has.** Across 50 repos inspected in depth and 100 more enumerated and screened, no memory platform, skills framework, extension, or plugin system earned wholesale adoption. Three of the largest systems (obra/superpowers at 309,852 stars, affaan-m/ECC at 293,818 stars, fainir/most-capable-agent-system-prompt) independently describe an architecture this stack already runs in production: files as canonical memory, skills as procedural memory, codified gates over prompt requests, fresh-context review, and verify-before-claiming. Installing any of them would create a competing source of truth, which the governing doctrine forbids. The value of the sweep is therefore refinements, not foundations, and the refinements cluster into five themes.

**First, proactivity needs a priced gate, not a better generator.** The cluster's top find, tao-hpu/awesome-proactive-agents (companion to a peer-reviewed TMLR 2026 survey), reduces intervention to one inequality: intervene iff expected benefit minus expected cost of interrupting exceeds a per-context threshold theta. thunlp/ProactiveAgent (ICLR 2025) proves why: an ungated frontier model proposes help almost always and is wrong about half the time (precision about 48 to 50 percent, false-alarm rate about 50 percent), and a separate reward/judge pass plus an explicit null output is the working cure. This stack has signals (crons, hooks) and surfaces (chat, Feed) but no named theta, no must/may/must-not scoring, and no accept/reject/ignore feedback taxonomy per lane. That is the single highest-leverage build in this catalog.

**Second, memory gains are all file-compatible.** Supermemory contributes a static/dynamic profile split (always-injected standing facts versus search-led recent context), typed fact edges (updates / extends / derives), and expiry as active forgetting. SuperLocalMemory contributes three-tier honest recall (supported / closest-only / not present, plus warming-up versus empty), erasure and correction that reach derived copies with receipts, and addition-only background maintenance with destructive fixes gated. Mem0 contributes ADD-only accumulation under the curated layer, multi-signal retrieval (keyword plus semantic plus entity), and temporal ranking. None of this requires a hosted store; all of it sharpens the existing file memory and its nightly synthesis.

**Third, the missing memory type is procedural and confidence-scored.** ECC's instincts are atomic trigger-to-action units extracted automatically from corrections and repeated workflows, confidence-scored 0.3 to 0.9, project-scoped, injected in a small ranked budget (about 6, threshold 0.7), and promoted to global or evolved into skills only on repetition across contexts. The stack's memory is semantic and episodic; its procedural learning is manual (doctrine lessons, bug log). Instincts are a complete, field-tested design for that missing layer, to be built natively.

**Fourth, instruction artifacts need the same testing discipline as code.** The doctrine already demands gate-wired regression blockers for code and state invariants. Prompts and SKILL.md playbooks are the one artifact class that still changes untested. Four repos converge on the cure: Superpowers' TDD-for-skills (pressure scenarios without the skill, record exact rationalizations, write the minimal skill, re-test), promptfoo's declarative prompt-eval pattern, openai/plugins' plugin-eval (a bundle ships with fixtures and a metric pack), and ECC's pass@k / pass^k reliability grading. Relatedly, vinicq/falsegreen-skill, the catalog's only ADOPT-CODE, audits whether blocker tests can actually fail, closing the one hole a pass-only gate cannot see.

**Fifth, boundary mechanisms beat UI mechanisms.** The extension cluster (Cluster 5) is mostly ChatGPT-web chrome that this stack starts past. What transfers is all at boundaries: turn-scoped capability tokens and compaction checkpoints that carry context but never authority (miuuyy/codex-chatgpt-web), a multi-format test-pinned conversation export contract (pionxzh/chatgpt-exporter), deep-link task invocation with prefill versus auto-run as separate flags, and per-task authoritative requirement checklists restored on compaction with completion validated against recorded evidence (GreenLv/codex-context-guard, kuroudo-ai/done-gate).

The ranked shortlist (Section 3) has 10 items: 1 ADOPT-CODE and 9 ADOPT-IDEA builds, mostly small or medium effort. The skip list (Section 5) is long and deliberate: hosted memory stores that would become a second truth, stale DOM-patching extensions, unlicensed or AGPL code where reuse is not clean, and any installer designed to rewire the harness it touches.

## 2. Trait-by-trait catalog

Entries are grouped under their primary trait; secondary traits are noted in the verdict line. Each entry names its source repo, gives a one-paragraph mechanism, quality evidence, and a verdict.

### 2.1 Memory

**Supermemory — supermemoryai/supermemory.** Mechanism: documents (chats, files, URLs, connector syncs) are ingested without caller-chosen chunking; a learning model extracts atomic facts into a temporal graph with exactly three edge types, updates (supersedes, history retained), extends (enriches), and derives (inferred across sources); temporary facts expire; each namespace gets an auto-maintained profile split into static long-term facts and dynamic recent activity, returned with search in one call; hybrid search covers memories and document chunks together; the agent surface is three verbs (save/forget, recall, context). Evidence: 31,480 stars, pushed 2026-10-30, MIT; vendor-reported #1 on LongMemEval, LoCoMo, ConvoMem (95 percent Recall@15 on LongMemEval) plus an open MemoryBench harness; docs are unusually honest about limits (not a system of record); caveat, the core engine is closed, so MIT covers the apps and plugins, not the engine producing the numbers. **Verdict: ADOPT-IDEA** (profile split, typed edges, expiry, per-category memory evaluation; see Shortlist #4). Not the hosted product.

**SuperLocalMemory (SLM) — qualixar/superlocalmemory.** Mechanism: a local-first, governed memory control plane (SQLite plus sqlite-vec canonical, other stores only after verifying against it) whose headline is honest tiered recall: every recall returns supported, closest-only labelled as such, or an outright not-present, with warming-up distinguished from empty, and an optional checker judging whether retrieved memories actually answer the question; writes pass admission checks with receipts, corrections are undoable, erasure reaches every derived copy (summaries, caches, indexes) with a verifiable receipt, an audit trail is hash-chained, facts are bitemporal with Ebbinghaus-style decay toward gist, background health passes enrich by addition only, and per-agent write attribution with trust scores defends shared memory against poisoning. Evidence: 269 stars, pushed 2026-10-28, about 5,303 tree entries showing real modules for RBAC, attribution, GDPR, integrity; benchmark caveats stated honestly in its own README (numbers are from an earlier architecture paper); four vendor arXiv preprints; AGPL-3.0 with a commercial license file. **Verdict: ADOPT-IDEA** (tiered recall, derived-copy erasure with receipts, addition-only maintenance; Shortlist #5). No code lift under AGPL.

**Mem0 — mem0ai/mem0.** Mechanism: a production memory layer whose April 2026 algorithm does single-pass ADD-only extraction (nothing updated or deleted in place; contradictions resolved at retrieval time), treats agent-confirmed facts as first-class, links entities across memories, and retrieves with fused semantic, BM25 keyword, and entity signals in one pass with temporal ranking (current versus past versus upcoming) and user/session/agent scoping. Evidence: 68,158 stars, pushed 2026-10-30, Apache-2.0, YC-backed, open evaluation framework; its README itself caveats that headline benchmarks (LoCoMo 92.5, LongMemEval 94.4) are managed-platform numbers including proprietary optimizations. **Verdict: ADOPT-IDEA** (ADD-only raw layer under the curated layer, multi-signal retrieval, temporal ranking). Also listed as a comparison target inside Supermemory's MemoryBench (Cluster 1 references).

**MemOS — MemTensor/MemOS.** Mechanism: a memory operating system unifying parametric, activation, and plaintext memory in composable MemCubes with a unified add/retrieve/edit/delete API, graph-structured inspectable storage, an asynchronous MemScheduler, and natural-language feedback correction; its local plugin line tiers memory as L1 traces, L2 policies, L3 world models, and crystallised Skills with hybrid FTS5 plus vector retrieval on SQLite. Evidence: 12,208 stars, pushed 2026-10-29, Apache-2.0; benchmarks are largely its own suite (OmniMemEval) and a single-framework before/after task claim, so treat numbers as vendor claims. **Verdict: REFERENCE with two ADOPT-IDEA elements** (gated skill crystallisation from repeated traces, with counts and a threshold; explicit per-partition sharing rules). Its traces-to-policies-to-skills ladder is ALREADY-HAVE in file form (daily logs to curated memory to synthesis to SKILL.md).

**Letta (MemGPT) — letta-ai/letta, current source letta-ai/letta-code.** Mechanism: LLM context treated as OS virtual memory: tiered core memory the agent edits via function calls, recall history, and archival storage, with agents as stateful services with persistent identity, now delivered as terminal UI, app server, channels, SDK, and cloud. Evidence: 25,306 stars, Apache-2.0, pushed 2026-10-18, but with real churn (rename, retired V1 server, repo migration declared in its own README). **Verdict: ALREADY-HAVE** (file memory with nightly synthesis is the same paging idea in auditable plain text). Borrow only the memory-block permission idea: blocks with explicit owners, agent-editable versus read-only.

**MemoryPlugin — memoryplugin/mcp-server with memoryplugin/agent-skills.** Mechanism: a hosted cross-tool bucket store of short texts with auto-generated Smart Memory category summaries, imported chat-history search, and uploaded-file search, exposed through a single-file MCP bridge (src/index.ts) forwarding calls to the vendor API with a user token; the companion skill teaches recall-before-assuming (search with the task's concrete nouns at start), store-before-finishing (atomic, dated, bucketed, with a one-line vetoable receipt), and an explicit do-not-store list. Evidence: 1 star (server) and 6 stars (skills), last pushes August and July 2026, README discloses its recommended install path is currently broken; all intelligence is in the closed hosted service, no benchmarks. **Verdict: SKIP** (thin stale bridge, maximal lock-in, already exceeded). Its protocol wording is REFERENCE-grade; the substance is ALREADY-HAVE.

**Honcho for Codex — plastic-labs/codex-honcho.** Mechanism: lifecycle hooks capture each session, queue the capture to disk locally first so capture never blocks a turn, upload in the background to a hosted API, and inject relevant context at session start, with active recall mid-task and memory scoped per directory, branch, or chat, shared across tools via one config file. Evidence: 66 stars, MIT, npm-published, last push 2026-09-01; the repo is a thin harness, the memory logic is the key-gated hosted API. **Verdict: ALREADY-HAVE** (local file memory with nightly synthesis, inspectable and portable). **llm-fact-log — siliconjungle/llm-fact-log.** Mechanism: statements are converted by GPT-4 into {a, relationship, b} triples appended to a log, entities and relationships embedded, questions converted to assertion triples with unknown terms snapped to the nearest existing entity by cosine similarity, answered by exact triple match. Evidence: ECC totals 293,818 stars, pushed 2026-10-30, MIT core; the continuous-learning-v2 SKILL.md was read in full and its thresholds, storage paths, and commands match the README. **Verdict: ADOPT-IDEA** (instincts built natively, Shortlist #2; Vault trust-boundary wording adopted as doctrine language). Do not install ECC.

Evidence: 0 stars, one day of commits (2026-03-14), MIT, coherent typed code read directly (search.ts, state.ts), in-memory state with a single JSON snapshot. **Verdict: ADOPT-IDEA** (count-triggered summarisation as an addition to clock-based synthesis; explainable hybrid search weights; skill recommendation by intent). Not the product.

**ChatGPT Exporter — pionxzh/chatgpt-exporter.** Mechanism: a userscript with dedicated exporter modules rendering one canonical conversation into Markdown, HTML, plain text, PNG, and JSON in three dialects (official, TavernAI/SillyTavern, Ooba), with citations and LaTeX preserved, bulk export, and format behaviour pinned by tests (markdown-format, json-export, export-content test files). ### 2.2 Initiation / Proactivity

**The intervention-timing field map — tao-hpu/awesome-proactive-agents.** Mechanism: not a conventional list but a field map organised around one inequality, intervene iff E[benefit of acting] minus E[cost of interrupting] exceeds theta, with every entry placed across five layers (signals, decision, action, memory, evaluation/self-improvement); it ships a deterministic standard-library pilot (about 200 lines, seed 13, expected output checked in) that seeds must/may/must-not windows from public HoloAssist annotations (benefit 4 / 2, violation cost 4, false-alarm cost 1) and scores five policies with a lambda-swept cost-weighted score that exposes the regime where silence is optimal; it adds an L0 to L3 feedback-depth table (explicit, implicit behavioural, outcome, long-term trust/disabling), three feedback maturity levels (log only; per-context threshold adaptation, called the smallest possible RL; learned policy), graduated action (silence through backchannel to full interruption as a menu of escalating costs), and historical cost evidence (about a 20-minute disruption arc per alert; sentiment toward a notification more than halves after eight others in two hours). Evidence: only 7 stars but three months old, CC0 per README footer, companion survey peer-reviewed at TMLR 2026 with public reviews, citations required to be verifiable, entries carry honest corrections after full-text reads; some 2026 arXiv entries could not all be independently verified and are treated as pointers. **Verdict: ADOPT-IDEA, the cluster's top find** (Shortlist #1).

**ProactiveAgent — thunlp/ProactiveAgent.** Mechanism: a desktop agent sensing via ActivityWatch, keyboard/mouse capture, and Chrome/VS Code extensions, spliced into an event stream; every interval (default 15 seconds) the model must return strict JSON with a proactive task or literal null, with null a first-class instructed output; a separate fine-tuned reward model judges proposals before surfacing (reported F1 0.918 versus GPT-4o at 0.67 on the same judgement, with general models scoring 0.0 on the false-alarm slice in their table), and rejected proposals are fed back with the judge's reasoning for a different retry, bounded at 3; human feedback is three distinct signals with distinct policy effects (accept executes, reject changes approach, ignore means busy and throttles rate, and no related proposals next turn after an accept); a Gym simulates environment, agent, reward model, and user to generate fine-tuning data (ProactiveBench, 6,790 human-annotated events). Evidence: 684 stars, Apache-2.0, ICLR 2025 paper, pushed 2026-05-12; honestly bounded results: fine-tuned models reach only about 66 percent F1 with false alarms still about 50 percent. **Verdict: ADOPT-IDEA** (gated-proposal architecture, three-way feedback taxonomy, four-cell scorecard of missed-needed / non-response / correct-detection / false-alarm; implemented as part of Shortlist #1). Do not adopt the sensing layer or code.

**ProactiveEval — liutj9/ProactiveEval.** Mechanism: proactive dialogue evaluation split into two separately scored stages, Target Planning (anticipate the need from raw environment data, judged against a reference target) and Dialogue Guidance (steer a simulated multi-turn conversation toward the target), over 328 synthesised scenarios across 6 domains built with a human-AI topic tree, refinement and noise passes, and multi-model reasonableness checks, with GPT-4o as default judge; its headline finding is that reasoning models showed degraded interaction and instruction-following in proactive dialogue versus non-reasoning models in its setup. Evidence: weakest in its cluster, 5 stars, no licence, all pushes on one day in August 2025, lowercase readme.md, LLM-judge bias unmitigated. **Verdict: ADOPT-IDEA (rubric only)** (score proactive lanes first on target correctness, then on delivery quality, hand-scored monthly on logged real interventions) / REFERENCE. SKIP the code (unlicensed, unmaintained).

**GPT Researcher — assafelovic/gpt-researcher.** Mechanism: a planner agent decomposes a query into research sub-questions, parallel executor agents retrieve from web and local documents per question, a named smart context-filtering step (Jev) keeps only context useful for each sub-question, and a publisher synthesises a cited report, with a recursive breadth/depth deep-research mode, multi-agent variants, and MCP support. Evidence: 30,402 stars, Apache-2.0, pushed 2026-10-10, PyPI and Docker distribution. **Verdict: ALREADY-HAVE** (workflow/subagent research pipelines here already implement planner/executor/synthesiser with stricter evidence rules), **with ADOPT-IDEA** for making the retrieval-to-synthesis context-filter an explicit, logged step, and for recursive question-tree expansion as a named escalation pattern.

**Momentum queues (inside the bootstrap prompt) — fainir/most-capable-agent-system-prompt.** Mechanism: a single README (3,325 lines in total) whose copy-paste prompt block is 2,949 lines, roughly 23,000 tokens, ordering a coding agent to build a self-improving agent operating system; its initiation core is a momentum engine maintaining five live queues (now, next, blocked, improve, recurring), a next-work selection rule (unblock the milestone, fix reliability gaps, convert repeated work into reusable assets, add eval coverage, expand breadth last), momentum ratchets (every success leaves a reusable asset), anti-stall rules (old blockers get decomposed with sidecar work in parallel; the same failure twice requires a guardrail, not a retry; idle time is filled with eval, memory cleanup, or backlog work), and tracked ratios including proactive versus reactive work. Evidence: 880 stars, MIT, pushed 2026-10-30, coherent and self-aware as a document, but no code, no tests, no reference deployment: every capability claim is about what a recipient agent might build. **Verdict: ALREADY-HAVE** for most of its architecture (see Section 4), **with ADOPT-IDEA slivers**: the five-queue checklist with a standing, always-nonempty improve queue, and the proactive-vs-reactive and memory-reuse ratios as tracked metrics. Do not run the prompt against the live stack.

**Follow-up prompt buttons — doggy8088/ChatGPTToolkitExtension.** Mechanism (proactivity aspect): configurable auto prompt buttons appear after each response on ChatGPT, Gemini, Claude, Phind, and Groq sites, defined in a CUSTOM_PROMPTS file, alongside its URL prompt delivery (catalogued under Execution). Evidence: 194 stars, pushed 2026-10-21, no licence declared. **Verdict:** the suggested-next-step behaviour is ALREADY-HAVE in this agent; the repo's adoptable item is its deep-link semantics (Execution). No adoption for this trait.

### 2.4 Abstract thinking

**Tree of Thoughts — kyegomez/tree-of-thoughts.** Mechanism: the Tree of Thoughts paper (arXiv 2305.10601) implemented as a searchable reasoning loop: generate candidate next thoughts from a node (propose or sample), evaluate each 0 to 1 by value scoring or comparative voting, search breadth-first with a beam or depth-first with backtracking, prune below a threshold, and answer from the best path, with model outputs validated against Pydantic schemas; the paper's headline is GPT-4 solving 4 percent of Game of 24 with chain-of-thought versus 74 percent with ToT. Evidence: 4,593 stars, Apache-2.0, pushed 2026-09-29; this implementation is one author's port now folded into his Swarms framework, and its repo description's general improvement phrasing is marketing of the Game of 24 result. **Verdict: ADOPT-IDEA (bounded)** (explicit generate-score-prune-backtrack discipline for named combinatorial classes: constrained scheduling, branching-hypothesis debugging, plan search; cite the paper). SKIP the Swarms-coupled code.

**Cognitive operations schema — ejentum/ejentum-mcp.** Mechanism: an MCP server whose tools return a cognitive operation before generation: a structured procedure (numbered steps, the failure pattern to refuse, and a falsification test) paired with an executable reasoning topology, a DAG of steps with decision gates, parallel branches, bounded loops, meta-cognitive exits, and escape paths; eight tools across reasoning, code, anti-deception, and memory harnesses, in dynamic mode (top-1 semantic match from a library of 679 operations) and adaptive mode (an adapter model rewrites every step with task-specific identifiers, paid tiers). Evidence: 16 stars, MIT wrapper, pushed 2026-06-11, npm and registry packaging, but the operation library and adapter live behind a paid hosted API with no published outcome benchmark in the README, so the claims that matter cannot be audited. **Verdict: REFERENCE** (borrow the procedure schema: add a failure-pattern-to-refuse field and a falsification-test field to local skills, and represent multi-branch procedures as small DAGs rather than linear checklists). Do not adopt the service.

**Inference-technique menu — algorithmicsuperintelligence/optillm.** Mechanism (abstract-thinking aspect): beyond the creativity patterns above, MCTS search over reasoning paths, plansearch, rstar, prover-verifier games, and LEAP, which learns explicit task-specific principles from a handful of worked examples including failures and prepends them as task rules; CePO's lesson is compositional, that wins come from stacking generate plus reflect plus verify. ## 3. Ranked adoption shortlist: top 10

All items are ADOPT-IDEA except #3, which is ADOPT-CODE (reviewed). Ranking is by expected payoff to this stack weighted by evidence and effort.

### #1. Price every proactive lane: theta gate, must/may/must-not scoring, feedback throttling
- Sources: tao-hpu/awesome-proactive-agents (ADOPT-IDEA); thunlp/ProactiveAgent (ADOPT-IDEA); liutj9/ProactiveEval rubric (ADOPT-IDEA).
- What to build or change here: for every cron and hook that can interrupt, write down its expected benefit, its interruption cost, and its theta in the lane's own definition; add a cheap gate pass (deterministic or small-model) whose only job is surface-or-stay-silent, separate from the generator, with an explicit null outcome; log feedback in the L0 to L3 shape (accept / dismiss / snooze, follow-through, outcome, long-term disabling) in a small per-lane state file and adapt theta per context from that log (maturity level 2, no learned policy yet); adopt graduated action (silent log, then digest/Feed inclusion, then direct message) as escalating costs chosen by the gate; grade lanes on the four cells (missed-needed, non-response, correct-detection, false-alarm) and on ProactiveEval's two stages (was the target right, then was the delivery good), hand-scored monthly on logged interventions. Lanes that cannot state a cost default to silent logging.
- Effort: **Medium** (one shared gate convention plus per-lane state files; the pilot's scoring shape is about 200 lines of standard-library logic to imitate, not import).
- Expected payoff: Highest in the catalog. Directly attacks the measured failure of proactive systems (about 50 percent false alarms ungated), protects trust (the ultimate negative reward is the user disabling proactivity), cuts cron-fleet cost via cheap-gate/expensive-actor, and turns existing restraint instincts into a scored, self-tuning system.

### #2. Instincts: a confidence-scored procedural memory layer, built natively
- Source: affaan-m/ECC, continuous-learning-v2 (ADOPT-IDEA).
- What to build or change here: a per-context observations log capturing corrections, error resolutions, and repeated workflows; a periodic (nightly, alongside synthesis) cheap extraction pass producing atomic trigger-to-action instincts with domain tags, evidence links, and confidence 0.3 to 0.9; scoping by context (goal, desk, life, per-project equivalent) with promotion to global only after appearance in 2+ contexts; session-start injection of at most about 6 instincts above a 0.7 threshold, ranked by confidence and relevance; a promotion path where mature instinct clusters are proposed as SKILL.md drafts, human-gated. Storage stays in the file memory tree, never in a second store.
- Effort: **Large** (new extraction pass, scoring, injection budgeting, and promotion workflow, plus regression blockers for the injection cap and scoping).
- Expected payoff: Fills the one memory type the stack lacks. Converts corrections the user currently repeats into learned behaviour automatically, compounds the trading book's lessons the same way as general work, and feeds the skills library with evidence-backed candidates instead of hunches.

### #3. False-green audit of the regression blockers
- Source: vinicq/falsegreen-skill (ADOPT-CODE, reviewed; fallback ADOPT-IDEA for its J1-J6 checklist).
- What to build or change here: adopt the skill as a candidate auditor over the gate-wired blocker tests specifically: run its six-judgement protocol (expected value borrowed from the code under test, mock asserted back to itself, assertion-free tests, and the other structural patterns) across the blocker suite, review every finding by hand (semantic findings err both ways), fix confirmed false-green blockers so each asserts an independently computed expected value, and add the audit as a periodic inspection step (not a per-commit gate, given model-judgement cost). Verify fail-direction on at least one known-bad mutation before trusting the pass.
- Effort: **Small** (one skill adoption plus one audit pass; fixes sized by findings).
- Expected payoff: Closes the exact hole in the blocker law: a gate proves tests pass on fixed code, nothing proves they would fail on broken code. One false-green blocker silently un-guards a past bug; this is the cheapest integrity upgrade available.

### #4. Memory profile and graph discipline: static/dynamic split, typed edges, active expiry
- Source: supermemoryai/supermemory (ADOPT-IDEA).
- What to build or change here: make the split operational in the nightly synthesis: a small always-injected static profile (standing facts and preferences that must colour every answer) maintained separately from dynamic recent context that stays search-led; label every supersession in synthesis with one of updates / extends / derives, with derives explicitly marked inferred-not-stated; give temporary facts an expiry field and have the nightly pass actively forget expired items rather than merely outrank them; add a small fixed evaluation set for the memory itself (knowledge-update, temporal, and preference questions, in the MemoryBench shape) run against synthesis output to catch recall regressions.
- Effort: **Medium** (synthesis prompt and file-format changes plus a small eval set; no new infrastructure).
- Expected payoff: Attacks the known failure where search misses a standing preference because it is not semantically similar to the query, sharpens contradiction handling and provenance audits, and gives memory its first regression signal instead of anecdote.

### #5. Honest recall and governed maintenance for the file memory
- Source: qualixar/superlocalmemory (ADOPT-IDEA).
- What to build or change here: memory search results carry an explicit tier (supported / closest-only / not present) and a warming-up versus empty distinction, so no agent silently builds on an irrelevant nearest neighbour; adopt SLM's completion definition for forgetting and correction as policy: an erasure is not done until summaries, caches, indexes, and derived syntheses are also clean, it produces a verifiable receipt, and corrections are undoable; codify the maintenance rule for the nightly pass: background enrichment may add only, moves and deletes queue for approval, every fix is reversible.
- Effort: **Medium** (search-result labelling plus forget/correction policy and receipt format; the policy half is small, the labelling half touches the search surface).
- Expected payoff: Directly serves two doctrine rules that currently rely on agent care (route failure is not impossibility; never claim absence from a failed lookup), and raises the forget/correction standard to match the stack's proof-before-green culture.

### #6. TDD-for-skills, rationalization tables, and description hygiene
- Source: obra/superpowers, writing-skills and verification-before-completion (ADOPT-IDEA); description rule completed by findscripter/everything-skills (ADOPT-IDEA).
- What to build or change here: for any new or materially revised high-stakes SKILL.md, first run pressure scenarios with subagents without the skill and record the exact rationalizations used to violate the rule, write the minimal skill against those specific violations, re-test, and plug new loopholes; add Thought/Reality rationalization tables to the highest-stakes existing playbooks (proof-before-green, save/read-back verification, delegated-handback verification); run a one-pass lint of all existing skill descriptions against the combined standard (triggers only, never summarise the workflow; must state the negative boundary) and fix violations; build the session-diagnosis idea natively as a small skill that audits a past session from its transcript across cost, plan adherence, quality evidence, and repeated work.
- Effort: **Medium** (method adoption is small; the description lint and table additions are a bounded pass over the existing library; pressure-testing applies per new skill thereafter).
- Expected payoff: Raises the reliability of the artifact class everything else depends on. Skills currently fail silently by being skipped or mis-triggered; this is the only inspected method that tests a skill the way blockers test code.

### #7. A skill/plugin adoption and eval gate: fixtures, reliability metrics, scan-before-list
- Sources: promptfoo/promptfoo (ADOPT-IDEA); openai/plugins plugin-eval (ADOPT-IDEA); hashgraph-online/awesome-ai-plugins scanner gate (ADOPT-IDEA); affaan-m/ECC eval-harness and AgentShield (ADOPT-IDEA).
- What to build or change here: a small fixed eval set per important skill (inputs, expected properties, rubric grader) run before a revised playbook ships, with regressions blocking, in promptfoo's declarative shape but implemented with existing workflow machinery; grade agent task reliability across skill/doctrine changes with pass@k and pass^k; require any third-party skill or connector entering the library to ship or receive a scan (secrets, permission breadth, hook and dynamic-execution risk, in the HOL scanner's categories and AgentShield's taxonomy) with the score attached to its library entry and unreviewed as the honest default; add a periodic sampled-output grading pass over real deliverables (research and report quality) as the organisational analogue of the trading record's grading.
- Effort: **Large** (eval sets, grading runs, and scan workflow are each real builds; can be staged: eval sets for the top skills first, scan policy immediately as a checklist).
- Expected payoff: Extends the blocker law to the last untested artifact class and to third-party adoption, and gives the stack a standing audit of its own configuration surface (skills, hooks, connector configs, permissions), which code gates do not cover.

### #8. Mechanical completion gates: done-gate evidence check plus context-guard requirement checklists
- Sources: kuroudo-ai/done-gate (ADOPT-IDEA); GreenLv/codex-context-guard (ADOPT-IDEA).
- What to build or change here: a turn-level check, implemented in the stack's own hook/workflow layer, that a completion claim is accompanied in the same turn by evidence (test result, exit code, command output, read-back) or is downgraded to unverified, blocking once rather than looping; and a per-task authoritative requirements file for long-running work (the SCOPE block in file form) that is re-injected on compaction or resume and against which completion claims are validated from the recorded evidence log, not from current context. Both are native reimplementations; neither tiny repo is installed.
- Effort: **Small to Medium** (the done-gate shape is deliberately minimal; the requirements file formalises an existing habit).
- Expected payoff: Converts proof-before-green from a rule an agent can believe it satisfied into a mechanism that fires when it did not, and protects long tasks from silently losing the very requirement they later claim to meet. Directly targets a failure class this stack has already suffered (a fabricated completion report in its own history).

### #9. Authority hygiene for compaction and tool turns
- Source: miuuyy/codex-chatgpt-web (ADOPT-IDEA).
- What to build or change here: adopt four rules as standing doctrine and, where a surface exists, as mechanism: (1) capability is minted per turn and expires with it, internal handles never exposed to the model, tools limited to those advertised for the active turn; (2) synthesis and compaction checkpoints carry context, never authority: the nightly synthesis is memory, not authorisation, and any authority after a resume is re-proven from the canonical record (approvals, files of record), never inherited from a summary; (3) for the highest-risk bridges, a human-send boundary (the draft-and-tap pattern generalised) instead of automation at the trust boundary; (4) no silent fallback identities or budgets: mismatches are rejected explicitly, fail-closed.
- Effort: **Small** (primarily doctrine wording plus an audit of resume/compaction paths; mechanism work only where a gap is found).
- Expected payoff: Cheap, precise hardening of the two surfaces most likely to be attacked or to drift (post-compaction resumes and delegated tool turns), stated in a form that can be regression-blocked.

### #10. Bounded hidden-rubric pass for ungated prose deliverables
- Source: DenisSergeevitch/chatgpt-custom-instructions (ADOPT-IDEA).
- What to build or change here: inside the relevant playbooks (stock reads, research syntheses, recommendations, reports), a step that constructs a task-specific rubric of 5 to 7 categories from the role's point of view, scores the draft internally per dimension, and revises any dimension under a set threshold, with a hard retry cap (the original's unbounded at-least-98 loop is not adopted) and the rubric never shown to the user; in the same pass, delete any legacy emotional-pressure lines (tip, penalty, career) from local prompts, per the author's cited negative results.
- Effort: **Small** (playbook wording only).
- Expected payoff: The highest value-per-effort item in Cluster 4: a cheap in-generation quality check for the large class of outputs no gate covers, where this stack's external gates check artifacts and code but not prose judgment.

**Near misses (adopt after the top 10, in order):** Mem0's ADD-only raw layer under the curated memory with multi-signal retrieval and temporal ranking (Medium; pairs with #4 and #5); everything-skills' typed skill relationships (requires / related / combines_with / supersedes) with separate quality facets (Small to Medium; pairs with #6 and #7); ambient-ai-chat's count-triggered summarisation triggers added to nightly synthesis (Small); MemOS's gated skill crystallisation counts (Small; largely inside #2); the explicit-versus-background context split from openai/mcp-extensions for any future always-on surface (Medium, surface-dependent); gpt-researcher's named context-filter step in research workflows (Small); Tree of Thoughts discipline for named combinatorial problem classes (Small); optillm's best-of-N-with-verifier and LEAP principle extraction for high-stakes answers (Small); the catalog-as-skill pattern for the next large local index (Medium, when an index needs it); the multi-format export contract for any transcript exporter (Small, when built); fainir's improve-queue checklist, 13-class failure taxonomy, and proactive/memory-reuse ratios (Small).

Vendor benchmark claims are labelled as such wherever they appear. Verdicts are transfer judgements against the reference stack described in the header, not general quality rankings: several SKIP verdicts are excellent products for a different stack.
