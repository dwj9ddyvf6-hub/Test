# Integration boundaries and adaptation checklist

The root terminal, UI, complete Worker router and deployment package were intentionally excluded. The modules here are components from an app boundary, not a ready-made host. In particular, do not infer app functionality, API routes or identity controls from copied business logic alone.

## Host-provided dependencies

1. **Runtime APIs:** several worker modules expect Cloudflare-style `env` bindings, `Request`/`Response`, crypto, cache, rate-limit or database handles; some are classic-script functions loaded by a host rather than ES modules. Set up an isolated adapter or test harness; do not bundle in the omitted Worker entrypoint.
2. **Secrets and providers:** supply tokens only at runtime via secret manager/environment. No real provider secrets/account data are included. The export does not prove Alpaca/IEX/SIP/Tradier or public-feed access. Re-check provider terms, scopes, freshness and availability before any acquisition.
3. **Templated deployment bindings:** `__RESEARCH_SERVICE_ORIGIN__`, `__PUBLIC_FEED_ORIGIN__`, `__CHARTSLECTOR_FEED_URL__`, `__SITE_SCOPE_ID__`, `__UPSTREAM_REPOSITORY_URL__`, and `__HOST_IP__` explicitly mark operator choices removed from source. They are placeholders requiring an independently reviewed, authorized integration. No placeholders are silently defaulted to an old production host.
4. **Persistence:** Psychology history/attempt integrations require D1-style SQL binding and explicit data-purpose/terms gates; migration `drizzle/0014_psychology_headline_tone.sql` is reference schema, not a complete database. Python service persists job inputs/outputs locally; do not add broker/account/portfolio data.
5. **Source data contracts:** adapters require exact provider, feed, adjustment, timezone, source receipt, bar/session lineage and expected interval. Preserve these fields and abstain on missing clocks, data gaps, revision uncertainty or mismatched sessions. Static readiness metadata in `worker/forecast-input-readiness.json` is an authored requirements catalog, not proof of availability.
6. **Build/wiring:** assemble only required module(s), respecting test/import dependencies. This export omits the full app build scripts and deployable bundle by design; it is not a terminal restore. Test the host adapter separately after component tests.

## Test scope

`node scripts/test-smoke.mjs` runs dependency-free synthetic checks; after installing pinned dependencies, `node scripts/test-components.mjs` runs the curated component suite; `python3 scripts/test-python.py` runs the included Python service unit suite; `PYTHONDONTWRITEBYTECODE=1 python3 scripts/test-chartslector-archive.py` runs five synthetic optional archive-reference checks (requires NumPy/Pandas and uses an explicit identity numba.njit test stub if Numba is unavailable). Full source-repository app/UI/Worker regression and production build checks were intentionally not copied or run because they require the excluded app bundle, private operational fixtures or deployment context. In the staging environment, no npm/Python third-party modules were preinstalled; `pnpm` attempted to initialize its default store under the restricted home directory and could not. No store was written. The dependency-free smoke path and Python test runner are checked separately below. All outcomes are local logic evidence only, not a live source, service, data rights, security, strategy or deployment proof.
